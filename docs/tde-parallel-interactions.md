# 《食梦者》并行双线交互改造清单（P5.5 设计稿）

> 目的：把「并行双线」从**引擎可跑**推进到**界面可用**。本文先盘点所有需要改的交互点、给出线框与口径，
> 再按波次施工；每一波完成后再动下一波，避免边改边发现口径冲突。
>
> 范围：`singleA / singleB / pick / parallel` 四模式共用同一套 hub；本文只描述**并行**新增/受影响的部分。
> 依赖：P5 批次 3 的 `parallel-runtime.js`（两份运行时、按座位路由、章对屏障）与 `hub-mode-view.js`（模式面板）。
> 非目标：真实 TDE 内容（P8）与 P9.5 的 4 人 2+2 / 2 人 1+1 / 3 人分选矩阵验收。
>
> **作用域（2026-10-29 修正）**：本文所有界面只对**声明了 parts 的战役**生效。生产内容里只有第五循环
> 《食梦者》会声明 parts；核心、敦威治、卡尔克萨、失落的时代、万象无终一律保持原样——不出现模式门、
> 不出现分线控件、不出现分屏。浏览器验收里的「双线演示」战役仅测试环境注册。

## 1. 三条新口径（本轮的用户决定）

1. **模式先于一切局外面板**：战役台面第一次出现时，先给「开局模式」选择；模式未定时不显示关卡选择、
   调查员、牌组、升级、战役记录、开局流程图等页签，也不能提前开始任何准备动作。
2. **并行 = 自由分线 + 人数相等才可开始**：
   - 第一次整备时，每个玩家自己选 A 线或 B 线（默认按人数对半，可随意改）；
   - 中途允许出现 3:1 / 1:1 等不平衡，但不平衡时「开始当前关卡」置灰并给出人数原因；
   - 只有 A、B 两组人数相等（且各 ≥1）时才允许开始；奇数总人数在模式选择处就置灰（无法相等）。
3. **出发准备左右分屏，局内不分屏**（2026-10-29）：出发准备页一条竖线分成 A/B 两栏
   （移动端改为上下）；进入关卡后牌桌保持单线，另一条线由双运行时在后台推进。

### 2.4 明确不动

- 单人/双人单线（`singleA/singleB`）的台面、关卡、结算：不出现分屏，也不出现分线控件。
- `pick` 的「同一时刻只跑一条线」：分屏仅用于 `parallel`；`pick` 仍是单线台面 + 关间切 part。
- 真实 TDE 的 8 章内容、结局矩阵：P8 范围。
- 存档格式：容器天然含两条线，不新增第二个存档文件；分屏只是投影。

## 3. 关键界面线框

### 3.1 首屏：模式先于一切（桌面 1440）

```text
┌──────────────────────────────────────────────────────────────┐
│ 诡镇奇谈 · <战役名>                            规则书 刷新 退出 │
├──────────────────────────────────────────────────────────────┤
│  开局模式                                                    │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐ │
│  │ 单线 A     │ │ 单线 B     │ │ 分选双线   │ │ 并行双线   │ │
│  └────────────┘ └────────────┘ └────────────┘ └────────────┘ │
│  并行双线需要两组人数相等（人数为奇数时不可用）               │
│                                                              │
│  队长： [座位 1] [座位 2] …                                  │
│  选择模式后才能选择关卡、调查员与牌组。                       │
└──────────────────────────────────────────────────────────────┘
```

- 判定：`campaign.mode == null` 时**只**渲染这一屏，页签栏为空、工作流只有第 0 步。
- 模式卡片直接用引擎 `hubSetMode` 的 `disabled/explanation`，不写第二套判断。

### 3.2 并行整备：自由分线 + 人数相等

```text
┌──────────────────────────────────────────────────────────────┐
│ 开局模式：并行双线                                            │
│ A 线：座位 1、座位 2（2 人）   B 线：座位 3、座位 4（2 人）   │
│ ✅ 两线人数相等，可以开始                                     │
│ 座位 1：A 线  [换到 B 线]                                     │
│ 座位 2：A 线  [换到 B 线]                                     │
│ 座位 3：B 线  [换到 A 线]                                     │
│ 座位 4：B 线  [换到 A 线]                                     │
│                                                              │
│ ⚠ 若有人换线后变成 A 3 / B 1：                                │
│   「两线人数必须相等（A 3 / B 1）」，开始按钮置灰             │
└──────────────────────────────────────────────────────────────┘
```

- 每个玩家只看到/操作**自己座位**的换线按钮；房主（座位 1）可操作全部座位。
- 人数不等不阻止选人/构筑/确认准备，只阻止开始；开始按钮的 `disabled` 来自引擎 `hubBeginScenario` 的
  `disabled/explanation`（与模式卡片同一口径）。

### 3.2.1 出发准备页：左右分屏（W2，已实现）

```text
┌──────────────────────────────────────────────────────────────┐
│ 双线出发准备   4/4 已准备   [阅读导入] [换位置] [开始] [重准备] │
├──────────────────────────────┬───────────────────────────────┤
│ A 线  第一幕：集结  [插图]   │ B 线  第二幕：午夜假面 [插图] │
│ 本线队长 罗兰               │ 本线队长 倒霉蛋              │
│ ┌ Roland 队长 · 换位置 ────┐ │ ┌ 倒霉蛋 队长 · 换位置 ───┐ │
│ └──────────────────────────┘ │ └─────────────────────────┘ │
│ ┌ Daisy 设为队长 · 换位置 ┐ │ ┌ Agnes 设为队长 · 换位置 ┐ │
│ └──────────────────────────┘ │ └─────────────────────────┘ │
└──────────────────────────────┴───────────────────────────────┘
```

- A 线在左、B 线在右，中间 1px 竖线；移动端上下两块（A 上 / B 下）;每线标题显示本线关卡名与插图。
- 每条线各选一名队长（`hubSetPartLeader`），默认每线第一个座位。
- 通用按钮（阅读导入/开始/重新准备）收在顶部一行；**换位置在每张人物卡里一键完成**（点了自己换到另一条线）。
- AI 角色的「换位置」只在房主视图出现（类似「设为队长」），房主点了 AI 才换线；非房主看不到。
- 人数不等时开始按钮置灰并给人数原因；非并行战役完全不进这些结构。
- 证据：`audit/tde-ui-browser.json`（`departure-parallel-desktop.png` / `departure-parallel-mobile.png`）。

### 3.3 局内牌桌：不做分屏（2026-10-29）

玩家只看自己那条线的牌桌。另一条线由 `parallel-runtime` 在后台推进，不做左右分栏，移动端也不改成上下两块。出发准备页的分屏仍是 §3.2.1。

## 6. 口径冲突与决策

1. **模式能否中途改？** 不能。模式在首屏确认后固定；想改只能重开战役（避免记录归属与流程回退）。
2. **分线能否在关卡进行中改？** 不能。只在「第一次整备」与关间（未有结算前）开放；一旦 `scenarioResults`
   非空即锁定，提示「已经开始游戏，不能再改线」。
3. **奇数人数**：`parallel` 在模式选择处置灰（无法两组相等）；即使后续改线也不能绕过。
4. **「准备完成」与「开始」分离**：人数不等只挡开始，不挡准备；避免玩家在等队友时被迫换线。
5. **分屏的隐私**：另一线只给公开投影；手牌、牌库、未公开剧情、私密事件一律不跨线。
6. **移动端**：竖线改横线，A 上 B 下；不做左右挤压。
