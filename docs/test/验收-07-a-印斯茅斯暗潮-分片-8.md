## 3. 逐卡失败清单

### 3.1 实现完整性失败（1 张）

**07315 回到深海（Back into the Depths，幕 1）** —— 维度：`implementation`（同时涉及玩家选择可达性）。
- 卡面（中文/英文）：
  - `Objective - 如果每位未击败的调查员都在伊哈·恩斯雷门扉，且调查员们持有下列每把钥匙
    （蓝色、红色、黄色、绿色），**你可以选择推进**。`
  - `Objective - If each investigator is at Gateway to Y'ha-nthlei and the investigators possess
    each of the following keys (blue, red, yellow, and green), **you may choose to advance**.`
- 实现：`src/cards/encounter-entries/theInnsmouthConspiracy/intoTheMaelstrom/07315.js:36-52` 只声明
  `actRule.objective(state)` 谓词（全员在 07320 + `keysHeldByGroup` 含蓝红黄绿）；
  引擎读点 `src/engine/act-agenda.js:207-210`：
  ```js
  const printedObjective = registeredEntry(act.originalCode || act.code)?.actRule?.objective
  if (typeof printedObjective === 'function' && typeof scenarioBehavior(state).checkObjectives !== 'function') {
    if (printedObjective(state, act, scenarioRuntime(state, events)) === true) advanceAct(state, events)
    return
  }
  ```
  即**目标成立后无条件自动推进**；全引擎没有「可选推进」原语（`actRule` 归一化/校验只允许
  `objective`、`onReveal`、`chapterSetup`、`setupSpawns`、`allResigned` 等键，无 `mayAdvance`/`optionalObjective`），
  内容层也没有 `checkObjectives` 覆盖。
- 后果：玩家失去卡面授予的「可以选择不推进、留在 Act 1 继续行动/准备」的权利；如果场上还有并行幕
  或想要先完成其它目标，规则顺序被改变。TIC 自身验收清单 §6 的「非 HIGH 长期回归项」里也明列
  「幕/议程『可选推进』」，说明这是已知待修项，而账本仍把 07315 记为 `verified`（证据只覆盖背面布置）。
- 证据（真实执行、标题含卡号）：
  `tests/acceptance-07-a-shard8.test.mjs`：
  `07315 回到深海：目标成立时 checkAct 自动推进，卡面「你可以选择推进」没有玩家选择（缺口）`
  —— 构造「全员门扉 + 四色钥匙」，`registeredEntry('07315').actRule.objective` 返回 true，
  调用引擎真实 `checkAct` 后断言 **未出现任何待决选择**（`asked === 0`）且 `actIndex` 已从 0 变 1
  （07315 → 07316）。
- 复现：`node --test tests/acceptance-07-a-shard8.test.mjs`（该用例现为「记录缺口」的通过用例：
  它锁定的是缺口本身；修复后应改为断言出现「继续留在本幕 / 推进到 Act 2」的选择）。
- 修法建议（主进程）：补可选推进原语（例如 `actRule.advance` 返回 `'optional'` + 引擎在
  `checkAct` 用 `requestChoice` 询问全体决策位；或新增 `actRule.mayAdvance(state, act, api)`），
  07315 声明它；补正反两向用例（选「继续」不推进、选「推进」才 `advanceAct`），并在账本把
  07315 从 `verified` 改为 `partial`/`remaining`。

### 3.2 通过但需登记的事项（已披露近似/口径说明）

1. **07314 洪水（密谋 3）正面**「若有一个[[古神]]敌人正在沉睡，将它翻至苏醒面」：参考实现是持续
   规则（AnyWindow 静默强制），本实现挂在 `agendaRule.phaseBegan`（每个阶段开始、幂等），所以
   「阶段中途新入场的沉睡古神」要等到下一阶段开始才翻面；条目注释已披露该接线方式。
2. **07316 深海之城（版本一）的「Either … or …」**：引擎无 OrCost 原语，拆成两条独立 `[fast]`
   行动；费用互斥、共同结算「降低任意非圣堂地点淹没等级」与印刷一致（审计 H15 修复），差异已登记。
3. **07332 水生异怪**「同一阶段不能攻击」：`enemy.movedViaHunter` 的引擎读点未把
   `lastHunterMove.phaseInstance` 暴露给攻击步（与 07214 同口径），实现用 `skipEnemyAttackThisRound`
   （本轮粒度），本章 `eventWindowInstances:true` 下落在敌人阶段攻击步；注解已披露精度残留。
4. **07337 深海恐惧症**「1 点不能防止的直接恐惧」：本作没有「防止/取消恐惧」的引擎层，
   以 `api.directHorror`（不分配给支援卡）为最接近的已接线口径；注释已披露。
5. **07321 沉没厅堂**「敌人进入后」：走 `enemyEnteredLocation` 窗口（`movement.js#relocateEnemy` 派发），
   不含「遭遇生成（spawn）」路径；卡面「enters」按 AH 规则默认指「移动进入」，若后续按 spawn 计入需
   另加读点——本轮不判失败，登记为口径说明。
6. **07311 剧本参考卡**有单卡条目（`scenarioReferenceEntry`），与其它循环的剧本参考卡惯例一致，
   不是「有行为无文件」；`entry-rules.js` 通过 `state.scenario.referenceCode` 分派。
