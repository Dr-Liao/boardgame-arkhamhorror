## 6. 原语与交互专项发现

### 6.1 原语（阻塞项，见 §3）

- 「查找遭遇牌库+弃牌堆取指定卡」在 05121 / 05122 / 05129 三个条目各自实现（其中 05121 与 05122 的 `findInEncounter` 逐字相同）；已登记入口 `api.takeEncounterCard(code)`（`src/engine/scenario-runtime.js`，05126/05143/05144/05147 已在用）可覆盖，且引擎 `encounterDeckCards()/encounterDiscardCards()` 返回快照副本，语义一致。
- 05129 的同一印刷句（强制=闹鬼）在条目与 `behavior.hauntedScript` 两处实现；应上收为单一 handler（条目声明 `haunted: [{ script: 'landlordsQuartersRats' }]` 与 `locationRule.onReveal` 共用）。

非阻塞的原语候选（仅登记发现，不判失败）：
- 「进入地点 → 检定(3) → 每点差值受伤害/恐惧」由 05135（战斗/敏捷，伤害）与 05140（意志，恐惧）各写一次 `locationRule.onEnter.effect`；引擎已有声明式 `onEnter.test`/`failChoice` 读点（`src/engine/ability.js`、`src/engine/movement.js`），可抽工厂。同型卡 05339/05340 也用 `effect()` 写法，属全局 P3 收口项。
- 「地点行动：每名/团队每场一次」在 05130/05132/05134/05137/05138 各写一次 `scenarioFlags.*BySeat` 记账；可考虑原语化（本次不阻塞）。
- 05137 传给 `api.investigate` 的 `allowNoClues` 选项当前引擎不读（`src/engine/actions.js` 已取消「有线索才能调查」限制）；无行为影响，属可删的死参数。

### 6.2 R1/R2/R3

- `audit/card-entry-compliance.json` 中本分片 42 个卡号**均不在**任何基线/watch 清单：`directStateWrite`（R1）、`reprintDuplicate`（R2）、`playConditionGap`（R3）各 0；`singleCardField`/`testWrapper`/`selfCodeInstanceLookup` 亦 0。本分片无重印别名卡（`duplicateOfCode` 为空）。
- 说明：`content/campaigns/**/behavior.js` 里仍有内容层直写（如 `grantAgendaClue` 写 `inv.clues`、敌人强制写 `enemy.*`）。R1 的审计口径是「**条目文件**直写运行时状态」（`audit:entries` 规则原文），内容层 behavior 不在该规则范围；本分片按其登记口径判定通过，并作为全局 R1 存量观察项记录（不属本分片新增）。

### 6.3 实现口径说明（非缺陷）

- 05119：图标选择在「有与本次检定匹配的图标」时只列匹配图标（不列必然无效的图标），结果与卡面「选择该卡已有的任意图标」等价（无效选择无收益）。
- 05142：强制只显式移动「未交战」敌人，已交战敌人随其调查员移动（AH 规则语义），与卡面「移动此处每位调查员与敌人」等价。
- 05122 幕 3、05123 幕 3、05126 密谋 4 的毁灭/场外处理分别依赖 `enemyScript`、`pendingAgendaDoom`+`behavior.agendaChain`、`api.removeDoom` 等既有读点，均有测试锁定。

### 6.4 交互

- 12 张玩家卡与 30 张非玩家卡均无需新面板：玩家卡复用现有动作/目标/费用窗口；非玩家卡复用「剧本书右侧场景行动 + 威胁区行动 + 自动强制」既有交互。05130 的场景行动走 `locationRule.actions/performAction`（P0-1 后选项 id 已按卡号去重）；05135/05140 的进入检定走引擎 `movement.js` 的 `onEnter.effect`（含失败差值窗口）。
- 多人/AI：所有选择走 `api.choice`/`requestChoice`（待决选择、可 skip），AI 由同一 `legalMoves` 枚举驱动，无真人/AI 分叉。
