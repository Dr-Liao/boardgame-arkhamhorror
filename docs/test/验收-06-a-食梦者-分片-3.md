## 5. 原语与交互专项发现

### 5.1 「声明即接线」违规（8 张，最高频失败类）

- `06120`/`06121`：`agendaRule.portResign` 只在条目里出现，全仓库无读点；撤退实际由 `definition.js` 的 `PORT_LOCATIONS` 逐地点 `resign:true` + `moves.js:699` 提供。要么删字段，要么让议程规则读它。
- `06123`–`06126`：`actRule.regionOptions` / `actRule.removeFromGameCodes` 声明后无读点（`onReveal` 内联同一份数据）。
- `06129b`/`06130b`/`06131b`：`assetRule.signs` 无读点（`resolve` 直接 `api.markers.add`）。
- 结论：这 8 张的**规则行为本身已实现**，失败原因是「声明字段没人读」按未实现计（AGENTS 不可协商项）。修复方式二选一：删除冗余字段，或由共享原语/behavior 读取这些数据键。

### 5.2 同句模板重复手写（06122–06126，原语维度）

- 五份 `REGIONS` 常量 + 「`filter(!visited)` → `choose` → `setScenarioFlag('pendingRegion')` → 全造访 `finish('resolution1')`」逐卡重复；`purgeEncounterCode` 在 06122/06124/06125/06126 复制 4 份。
- 正确形态：behavior 提供单一「结算背去哪里」原语，条目只保留数据（`regionOptions` / `removeFromGameCodes` / `purgeCodes` / `priestShuffle`），这正好也是 5.1 里已声明未读字段的接线方向。

### 5.3 结果对象字段误用（06131 / 06132）

- 引擎 `src/engine/tests.js:1875-1885` 构造的 result 有 `value/difficulty/token/drawn/cancelledTokens/source` 等，但**没有 `successBy`**；章节 `afterTest` 收到的是该对象。
  - `06131` 用 `result.successBy` 判「≤1 点」→ 恒 false → 过度触发 1 点恐惧。
  - `06132` 只读 `result.token`（= `drawn.at(-1)`）→ 对 cultist「再揭示一个标记」后的链式揭示漏触发；同章 `behavior.js:261-262` 的 `has()`（token + drawn，且过滤 cancelledTokens）是正确口径，可复用。
- 建议：把 `successBy` 写进标准 result（与 `skillTestSuccess` 窗口上下文对齐），或章节侧统一用 `result.value - result.difficulty` / `resolvedTokens`。

### 5.4 生成时未取出原卡（06127b / 06128b）

- `06127b` 生成乌撒之猫时未 `api.takeFromSetAside`：setup 已把该卡放进 `scenarioZones.setAside`（`behavior.js:353-364`），`spawnEnemy` 不清理场外集合 → 同卡同时在 play 与 set aside。
- `06128b` 从遭遇牌库顶弃到生物敌人后未 `api.takeEncounterDiscard`：同卡同时在 play 与遭遇弃牌堆；本关多张幕背面会把遭遇弃牌堆洗回牌库（`shuffleDiscard`），可能重复生成。
- 同仓正确口径：`theSecretName/05126.js:24`、`_shared/spiders/06101.js:39`、`06185.js:49` 均为「取出后生成」。

### 5.5 已核实无问题的原语/交互面

- 掩藏：`src/engine/veiled.js` 的 `canFlipVeiledLocation` / `flipVeiledLocation` + setup `locationsStartRevealed:true`，15 处掩藏地点的翻面门槛/故事面链接均正确。

- 蜂拥：`api.swarm.place` 按规则从「你的牌库顶」取 X 张（`docs/tde-primitives.md` p39；`swarm.js:51-77`），06128b 加蜂拥卡语义正确。
