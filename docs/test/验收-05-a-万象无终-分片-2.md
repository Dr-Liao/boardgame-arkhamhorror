## 5. 原语与交互专项发现

### 5.1 R1 直写与审计口径（05055b）

- `theWitchingHour/05055b.js` 的 `onReveal` 把 `state.scenarioZones.setAside` 存进局部变量后 `splice` 原地删除安妮特，属条目直写状态。正确写法是 `api.takeFromSetAside('05057')`（`api-misc.js:853`，与同章 `05053`/`theSecretWages` 的条目录点一致）。行为结果（生成 05057 到女巫圆环）已通过新用例，失败点仅在原语合规。
- 同类模式在**内容层** behavior 中普遍存在（`takeFromSetAside` 辅助函数同样 `list.splice`；atDeathsDoorstep/05073 等直接改 `inv.resources`）。内容层行为是规程允许的读点，不属于条目级 R1；但建议 P2 结构性债务轮次一并用 `api` 收口。
- **工具盲区**：`tools/audit-card-entry-compliance.mjs` 的 R1 正则不追踪 `const x = state.y` 别名与索引式写入，因此 05055b 未进基线（本分片 55 张中仅此 1 条）。建议扩规则后再 `audit:entries:write`，避免同类 R1 继续以「无违规」通过。

### 5.2 近似与披露

- **05056「你面前的地点均相互连接」**：本 Mod 把「面前地点」实现为 `scenarioFlags.frontOf` + 访问限制（`behavior.frontLocationError`），「互相连接」由 definition 的印刷符号连线图承担——7 张女巫作祟之林同为 `squiggle` 符号且互在 links 中，`linkSymbolLocations` 生成全连通邻接表（数据被引擎移动真实读取）。效果等价（act4 时玩家可进入并互达），但这条子句没有独立读点，报告中登记为**已披露的数据实现**。
- **05067「每个银暮秘社敌人获得胜利 0」**：在 `enemyDefeated` 时把胜利 0 的敌人放入 `victoryDisplay`（供幕间 II 分支清点），0 点不改变分数；等价实现，已登记。
- **05062**：条目里「commitIconMultiplier 只算 1 个图标」的注释是旧近似描述；实际引擎对非执行者每次检定限定 1 张（`tests.js:522`），图标按印刷值计入，与卡面一致。这是一条**过时注释**（建议删除近似描述，避免审计误判）。
- **05096/05099** 的注释声称把近似写进 `status.json` 的 approximations/gaps，但仓库内不存在该文件（TCU 账本因 `web/campaign-presentation.js` 未提交 WIP 无法重签）。建议 P2 账本重签时把这些近似落进 `audit/tcu-migration.json` 的 `remaining`，或删掉「已登记」措辞。

### 5.3 交互

- 本分片没有新增面板：地点/幕/议程行动走剧本行动栏与剧本卡归属（`scriptCards` / `locationRule.actions`），威胁区行动走共享 `threatAction` 展开，谈判走引擎通用 Parley，选择/目标/技能/卡牌走 `api.choose`；05089/05102/05107 的「密谋牌库旁」与 05100/05102/05103 的闹鬼授予由 P1-13 的观察投影（`agendaAside/hauntedGrants`）与 `web/tcu-ui.js` 承载。故无新增浏览器证据义务；Node 用例已覆盖各选择的可执行/可放弃路径（如 05076 费用不足不消耗团队次数、05058/05060 的每轮上限）。
- 结构观察（非阻断）：atDeathsDoorstep 的幕/议程/地点规则仍在章节 `behavior.js` 里按卡号分派（05066–05070 的 `ACT_ADVANCE/AGENDA_ADVANCE`、05071–05077 的 `actions/performAction`），属 full-scan D4 记录的存量结构性债务（P2），本轮不判失败。
