## 3. 逐卡失败清单

### F1 `07189` 附魔护甲 · 维度：implementation（medium）

- 原因：卡面「如果检定失败，弃掉附魔护甲并将刚刚放置在上面的伤害和/或恐惧分配到别处」被写死为回到护甲所有者：`api.playerTools.testAssignedHarm` 失败分支固定 `api().harm(owner, …)`，没有提供任何承受者/目标选择；伤害由同地点其他调查员放到护甲上时（多人数常见），会被错误地转给所有者而不是由原分配者另选目标。现有用例 `tests/tic-player-guardian-seeker.test.mjs:134-137` 正是按「回到 owner」写期望，属把错误行为固化成期望。

- 既有证据（按错误行为写期望）：`tests/tic-player-guardian-seeker.test.mjs:134-137` —「transfers control, tests owner, and reassigns only new harm on failure」把「回到 owner」当成期望。
- 复现：`node artifacts/acceptance/07-a-5/probe-defects.mjs` → exit 1，`FAIL 07189 附魔护甲：失败后的伤害/恐惧可「分配到别处」（有承受者选择）`。

- 修复建议：失败分支改为重新走伤害/恐惧分配（复用 `assignHarm`/`requestChoice`，在护甲被弃置后列出合法承受者/支援目标），并把既有用例改成真实选择路径。
