### 6.2 专项发现

1. **动态数值读点缺口（3 张）**：commit 的 iconBonus ctx 没有 getStat/api，08052/08065/08078 只能读 cards-data 印刷技能值；一旦属性被修正（支援 +1、伤害/恐惧、临时效果），图标数就错。建议主进程把「有效技能值」读点接进 iconBonus（条目注释已登记 primitive request），这是一次性引擎能力，可同时修 3 张及未来同类卡。
2. **沉静伤害读点已存在但卡片未声明（3 张）**：引擎 harm-threat.js:206-214 已支持 `flags.composureDamage:true` 的「非直接伤害必须先分配给本卡」，但 08056/08069/08081 仍只写 `composure:true`（仅恐惧侧）+ 08056 的 1 点 redirect 近似。逐卡加一行 flags 即可等价实现，属低成本高一致性问题。
3. **引擎窗口选择导致的行为偏差**：08064 把「抽牌前指定卡名」做成「抽牌后按已抽到的牌选名」，使卡面「猜中才可取消」变成「总能取消任意一张非弱点」；08087 把「下一个远程/枪械攻击行动」放宽为「本回合所有检定」并缺借机攻击豁免。这两处是窗口原语限制，建议按 primitive request 修（抽牌前命名窗口/延迟 noOpportunityAttack）。
