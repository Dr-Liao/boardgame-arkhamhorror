## 5. 原语与交互专项发现

### 5.1 章节卡确实被引擎/流程读取的证明（抽样）

- 幕/密谋：`definition.js` 的 `scenario.acts/agendas` 由 `content/campaigns/theForgottenAge/card-data.js#stages` 从 `cards-data` 生成，引擎 `reveal.js`/`phases.js` 调 `behavior.actReveal/agendaReveal` 执行背面；本分片 04315–04323、04162–04167、04238–04243、04345–04347 均在校验中触发。
- 地点：`location()` 生成的 `symbols/shroud/cluesPerInvestigator` 与探索牌库/符号连线真实参与布置（`setupPlan`/`shiftSlot`）；04176/04180/04183/04185 等古代地点入场强制经 `exploreFrom → shiftSlot → enterAncientFace` 触发（新增测试用真实 `behavior.performAction` 走通）。
- 纯数据卡：04168 的「2 个行动探索」、04169 的「6 张手牌门槛」、04172 的「不能获得资源 / 3 资源探索」、04173 的「伤害或恐惧」均在 `behavior.EXPLORE_SPECS` 有唯一读点；04167 的「在大神庙共同支付」由 `scenario.acts[2].objective = { type:'clues', perInvestigator:2, atLocation:'templeRuins' }` + 引擎 `act-agenda.js#groupPayment` 读取。
- 混沌标记：04314/04161/04237/04344 的四符号简单面/困难面在 `tfa-chaos.js` 逐条实现，新增测试覆盖 04314 的骷髅/异教徒/石板/旧神与 04161/04237/04344 的困难面。

### 5.2 原语缺口 / 待修项

1. **R1 直写（8 张，见 §3）**：需要 `api.scenarioFlag`、`api.moveCardTo`（手牌→牌库/弃牌堆）、`api.shuffleCardIntoDeck`、`api.shuffleIntoEncounterDeck`、`api.setRelicOfAges` 一类窄原语收口；修完跑 `npm run audit:entries:write` 收紧基线。
2. **`treacheryRule.threatArea` 无读点（04189/04190/04261）**：建议删掉这三处错误/冗余声明（04189/04190 与卡文不符），或让失落时代读点支持该字段并补测试。
3. **可选 `[reaction]` 自动结算（04174/04179/04256）**：建议改为 `api.choose({ kind:'reaction', canSkip:true })`；若保留自动结算，必须在迁移账本 `gaps/remaining` 显式披露为近似。
4. **R5 观察项**：04190 的「显现-检定」为手写 `api.test` 包装（`audit` watch `revelationTestStubs`），因难度 = 1 + 古代地点数，声明式 `treacheryRule.test` 表达不了，可登记 `primitive-plan escape` 而不是留在观察债。
5. **审计口径漏检**：`audit-card-entry-compliance.mjs` 未捕获 `state.scenarioFlags.x =`、非污染变量（`nexus.doom`、`yig.damageTaken`）直写，建议扩大 R1 检测；否则账本「R1 112」低估实际债务。
6. **单卡私有状态（R4 类，非阻断）**：tcoa 的 `inv.tfaHallsShortcutRound`（04248–04250 共用）、`inv.tfaTowersRound`（04255）、tbb 的 `enemy.tfaAttackBoost` 等写在章节 behavior 里，绕过了条目 R4 扫描；建议后续改用 `limit`/通用回合标记原语。
7. **交互复用证明**：本分片没有新增面板；选择/目标全部复用既有面板——场景行动栏、剧本书卡片旁行动（`scriptCards`）、威胁区行动、谈判（parley）、危境/故事二选一、技能与目标选择。真实浏览器证据见 §4（桌面 1440 + 移动 390 共 8 例通过）。
