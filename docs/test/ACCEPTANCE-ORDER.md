## 3. 验收维度（缺一不可）

每张卡至少通过以下五维，单元内逐卡记录结论：

1. **实现完整性**：卡面印刷文本的每个子句都有本地读点（条目描述子 / 引擎窗口 / 内容层行为 / 通用数据规则），无「声明了没人读」的字段；近似实现必须显式披露，不得冒充等价；重印只实现一次、别名可解析。
2. **原语设计**：只使用已登记原语；跨卡同句规则不重复手写；新增状态字段有引擎读点与测试；无直写运行时状态（R1）、无重印双实现（R2）、回合限制缺失（R3）等合规问题；原语本身可复用、有测试、无死代码。
3. **玩家交互性**：玩家能看到并完成该卡的相关选择/目标/提示/支付；AI 与真人席位、多人/联机路径可用；新交互复用既有面板语言；桌面 1440 与移动 390 可达（涉及界面时必须有浏览器证据）。
4. **证据**：至少一条真实执行的测试/浏览器用例逐卡覆盖（测试标题含卡号），本地重跑通过；不得只采信既有账本、README 勾选或「条目存在」。
5. **合规与回归**：`cards:check` / `cards:encounter-check` / `audit:entries` 通过；行为改动前后 replay 无漂移；`test:fast` 无新增失败。

**判定**：五维全部通过 → 该卡 `verified`；任一维度失败 → 该卡保持未验收，写入报告「失败清单」，附维度、原因、证据与复现步骤。

## 4. 单单元执行流程

1. 锁定范围：卡号清单、所属卡包、对应测试文件与内容层模块。
2. 独立复核（不采信既有账本结论）：逐卡核对卡文 ↔ 实现 ↔ 引擎读点 ↔ 测试；静态检查原语与合规（`npm run audit:entries` 等）。
3. 交互复核：找出该批卡涉及的选择/目标/面板，跑对应 Node/浏览器用例（必要时补 1440/390 截图，存 `artifacts/`）。
4. 补证据：缺逐卡证据的卡，补有真实断言的测试（标题含卡号）；**不得**为过验收写空断言或只断言「条目存在」。
5. 落报告：`docs/test/验收-<unit>-<名称>.md` + 同名 `.json` 结论（格式见 §5）。
6. 切换：通过的卡生成验收账本（`audit/<unit>-acceptance.json`）与 `src/cards/<unit>-acceptance.js`，在 `import-cards.mjs` 接线，重新生成 `cards-data.js` / `catalog-report.json` / 展示报告，跑门禁。
7. 更新本文档进度表，提交一次「验收：<unit>」。
8. 当前文件全部通过后，核对账本与图鉴，删除对应的 Markdown 和 JSON 报告，再运行该单元的账本复算。若生成配置读取报告，先将已锁定的卡号范围及通过结论保存在单元配置中。保留逐卡账本、测试和进度表，再转入下一份文件。

**职责边界**：审计子智能体只写「验收测试文件 + 报告」，不改引擎/卡条目/账本；账本生成、`import-cards` 接线、派生文件再生成与门禁由主进程统一执行（账本是共享文件，单一写者）。

## 5. 结论文件格式

`验收-<unit>-<名称>.json`（机器可读，主进程据此合并）：

```json
{
  "unit": "01-a",
  "generatedAt": "2026-11-24",
  "scope": { "cards": 116, "selector": "pack=rcore" },
  "verdict": "pass | partial | fail",
  "verifiedCodes": ["01501"],
  "failedCodes": [{ "code": "01502", "dimension": "implementation", "reason": "…", "evidence": "tests/…" }],
  "excludedCodes": ["01000"],
  "dimensions": {
    "implementation": "pass | fail",
    "primitives": "pass | fail",
    "interaction": "pass | fail",
    "evidence": "pass | fail",
    "compliance": "pass | fail"
  },
  "evidence": [{ "file": "tests/…", "test": "…", "codes": ["01501"] }],
  "notes": "…"
}
```

Markdown 报告必须包含：范围与基线、五维结论、逐卡失败清单、证据清单（文件/用例/命令与结果）、原语与交互专项发现、建议后续动作。

## 6. 已验收段复核

`01 core`、`02`、`03`、`04 玩家/调查员`（合计 1,006 张）历史账本只证明「逐卡主要效果」，本轮新口径要求原语与交互也复核。每单元验收完成后，按顺序对这些历史单元做抽样复核（每循环 10% 或至少 20 张，覆盖调查员/玩家/遭遇/章节），发现问题记入对应报告，不撤销 `verified` 但必须登记待修项。抽检记录追加在本文件 §8。
