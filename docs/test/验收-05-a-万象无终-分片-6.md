## 5. 原语与交互专项发现

### 5.1 重印（R2）系统性问题（本分片 3 张 + 跨切面）

- 05266 / 05268 / 05269 与 02090 / 02091 / 02221 同名同文，属跨循环重印；`cards-data.js` 没有 `duplicateOfCode/duplicatedBy`，`_reprint-aliases.js` 也无映射，导致「重印只实现一次」失效。
- 同族 2026 核心重印 12166 / 12167 同样未登记重印关系且没有条目（可用性风险，超出本分片范围，供 12-a 复核）。
- 建议：先补 cards-data 重印元数据（唯一事实源），再按 `_reprint-aliases.js` 白名单登记，保留 canonical 实现（02090 的光环应上收到 02090 条目，02091 声明式测试直接复用，02221 的 `encounterResolveCampaigns` 扩到 tcu 或改为共享条目）。

### 5.2 R1 审计盲点（05236）

- `audit-card-entry-compliance.mjs` 只把 `state/inv/location/...` 字面根、`context.*` 写与「由这些根派生的局部变量」算 R1，`resolve: ({ source }) => source.removedFromGame = true` 这类**resolve 参数直写实例**会漏检。
- 建议扩大 R1 检测：把 resolve/criteria 解构参数（`source`/`target`/`asset`/`enemy`…）纳入污点根，并补 `api.removeAssetFromGame`/`exileAsset` 原语供 05236 收口；否则 fix-plan 宣称的「TCU R1 清零」不成立。

### 5.3 同句模板未上收（05269/05270，P2-3）

- 「加入任意调查员威胁区」在 02221/05269/05270 三份，05270 与 05269 的 `encounterResolve` 逐字相同；应按 §4.3 建共享工厂/声明式 `threatAreaOnReveal` 数据键，05270 只保留 `harmInterceptor` 差异。

### 5.4 已披露近似（判 pass，但主进程应同步账本/文档）

- 05238：无「冒险参考牌底」原语 → `scenarioFlags.fateCards` 承载 4 张命运卡；命运敌人翻回敌人面用 `spawnStoryEnemy` 近似（本关没有能选中该卡的效果）；失踪人口记录口径近似；结局 XP 由 P9 战役流程统一结算、不在 resolution 发放；幽灵敌人地点限制不适用于本章（behavior 覆写 canFight/canEvade）。均登记在 `behavior.js` 的 `migrationHistory`（`notes.js`），但 `audit/tcu-scenario-acceptance.json` 的 `approximations` 仍为 `[]`，P2-2「逐卡账本去假绿 / 账本与真实状态一致」未完成。
- 文档漂移（P2-6）：`notes.js` 仍称「远古恶魔、寒冷刺骨两个核组不参与牌堆」，但当前 HEAD 的 UAD 遭遇牌库实际含 `ancient_evils` 3 张 + `chilling_cold` 4 张（`definition.js` deckGroups 已收），`story-text.js` 的 SETUP 也写「缺少两个核组」；05230 条目顶部注释仍称「附属限制与 reaction 未实现」，但当前 D1-5 修复后已接线（`hostCannotAttackEngaged` / `hostAttackConnecting` / `activateFirearmFight` 窗口）——属过时披露，建议随 P2-6 清理。
- 展示层低项（不影响 verified）：05239「将本卡放在密谋牌库旁作为提示」未做旁置投影（效果本身由 05086 条目 `fightPerMarker` + behavior 生命加成实现）；05242「把面前地点放回中央」由幕切换解除移动限制实现，无空间摆放投影。二者为低优先展示项，建议登记 remaining。

### 5.5 交互复用证明

- 阵法：`behavior.actions` 生成 `scenarioAction`（现有场景行动栏），成功后的点燃/熄灭走 `api.choose`（现有选择事务）；火盆状态 = 地点 marker（`brazier`，`table-components.js:146` + `tcu.badge.brazierLit` locale），观察投影 `locationStateProjection`。
- 闹鬼：`definition.js` 的 `haunted.effect` 由引擎 `haunted.js` 的闭集子句（choice/damage/horror/doom/discardChosen/script）结算，选择走既有 `requestChoice`。
- 命运卡/剧情支援：`api.giveAsset` 进普通支援区，「不占盟友槽」用 `slotsOverride`；命运敌人进普通敌人区/威胁区交互。
- 谈判约瑟夫：`behavior.actions` 仅在未封锁且同地点列出（`flags.noParleyJosef` 唯一读点），成功翻面走 `api.flipEnemy`。
- 结论：无新增面板，全部复用既有界面 token；桌面/移动的 1440×950 与 390×844 实机证据已存在于仓库（见 §4）。
