## 6. 原语与交互专项发现

### 6.1 原语 / 数据接线（非阻塞，登记给主进程）

1. **act/agenda 条目 flags 与 definition 双份数据**：06248–06253 六张条目的 `flags`（`advanceRule`/`takeCluesOnEnemyDefeat`/`placeSetAsideLocations`/`finishOnAdvance`/`advanceChoice`/`revertOnAdvance` 等）当前**无读点**；behavior 读的是 `definition.js` 的 `state.acts/agendas` 上的同名字段（两处值一致，规则实际生效）。definition 注释自述「单卡条目 flags 携带同一份键，索引重建后优先」，但该「条目优先」管道尚未接线，属 P3 债务（与 04-a/05-a 的分片发现同型）。同理 06275 的 `flags.setupDoom`/`anySkillTest`/`removeFromGameOnSuccess` 无读点（behavior 以硬编码实现同一规则：`afterDeckSetup` 放 1 毁灭、`performAction` 任意技能检定、成功 `removeAgendaAside`→`removedFromGame`）。
2. **「最近的敌人」原语候选**：06268 与 06270 各自手写相同的 `nearestEnemy`（仅同地点/相邻）；仓库已有 BFS 距离口径（如 TCU `nearestCultist`）。属第 2 张卡，建议登记为原语候选并在修复 6 张失败卡时一并上收（`nearestEnemyAtDistance`）。
3. **参考卡伤害（Distortion）唯一状态源**：本章为 `state.markerCounts.reference`（`chaos.js#referenceDamage`），而引擎 `swarming.js` 的 `scenarioDamage` 口径读 `scenarioFlags.referenceDamage`。两套口径并存且无同步点，导致 06273/06274 失败；建议统一为「命名计数器（markerCounts）」并让 `swarming.js` 读取时回退（或章节 setup 同步写 flag）。这是跨章节原语口径问题，影响 06273 及任何 `Swarming X = scenario reference card damage` 的敌人。
4. **剧情资产离场移出**：通用读点是条目级 `removeFromGameOnLeave`（引擎 `assets.js`），本章却用 `removeStoryAssetOnLeave`/`pickmanRemovedOnLeave`（无读点）。修复 06251 应让 06266 声明 `removeFromGameOnLeave` 或由章节在离场钩子读 `removeStoryAssetOnLeave`。
