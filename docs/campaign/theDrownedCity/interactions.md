# 沉没之城 P4 交互与验收

关卡用 `scenario.mechanics.tdc` 声明本轮可用的任务、路线、区域和字形。发动交互经由 `api.interactions.tdc` 或剧本运行时的 `mechanics.interactions.tdc` 进入同一待决选择事务。界面以服务端的候选和 `legalMoves` 为准，部位按钮的禁用原因来自动作校验。[交互事务](../../../src/engine/tdc-interactions.js) · [观察投影](../../../src/integration/tdc-view.js)

| 交互 | 牌桌与规则读点 |
| --- | --- |
| 任务 | 候选在领取前按调查员与任务去重。本人才能看到待决候选与当前任务进度，演出快照也按座位过滤。 |
| 路线与地图记录 | 领队选定东西路线。区域划除只接受当前路线允许且尚未划除的位置，摘要展示已划除状态。 |
| 字形 A–Z | 摘要列出 26 个字形。结算后公布已翻译的文字，未触发的译文只留在服务端。 |
| 文物 | 先选已获得的文物，再选存活的持有人。分配可取消。持有人败退时，按现有距离规则列出并列最近的幸存者并转移原实例。 |
| 地点和部位 | 地点重排先整体检查目标格，再更新位置和连接。地图显示敌人主体，专用板块分别显示部位的战斗和躲避动作。 |
| 剧本书 | 当前幕或议程卡通过 `scriptCard` 提供行动。“关卡设置”位于提示卡下方，特别规则优先，后续剧情与结局默认折叠。实际演出中的私人分支走现有座位投影。 |

`npm run test:tdc` 验证选择、存档恢复、部位动作和隐私。 `npm run test:tdc:p4:browser` 使用真实大厅、服务端规则和正常动作提交，从测试夹具设置可操作的牌桌。两个视口分别验证取消与焦点恢复、提交失败重试、无候选、区域划除、字形、重排、多人接管、部位行动、幕／议程归属，以及指南加载失败重试与中英阅读。正式章节的逐章指南及剧情分支接线属于 P7。
