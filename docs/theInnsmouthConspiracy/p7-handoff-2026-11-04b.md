## 5. 本批踩过并修掉的坑（接手前必读，能省你一整天）

1. **重复 API**：我给 07105 加了 `api.scenario.preventEnemyReady`，结果运行时里**早就有同名方法**（食梦者 06092 在用），对象字面量后者覆盖前者，TDE 用例当场红。**新增 api 前先按方法名全量 grep**。
2. **载具移动不动卡面**：`vehicles.moveVehicle` 原本只改登记表并搬乘客，剧情支援自身的 `location` 停在原地，导致渔船第二次 `[action]` 的范围判定读旧地点。已修（只在已有 `location` 字段时同步）。
3. **两个 api 面形状不一致**：能力面把机制入口摊平到顶层（`api.vehicles`），场景运行时用 `api.mechanics.vehicles`。现在能力面两者都有且**共用同一个实例**。
4. **ESM 循环**：卡条目经 `_shared.js` import `vehicles.js` 会拉进 `ability.js` → `deck/availability.js`，抛 `Cannot access 'strictAcceptedCodes' before initialization`。读函数已拆到叶子模块 `src/engine/vehicle-state.js`。
5. **`road.columns` 的键是地点实例 id**，不是卡号；第一版按卡号查永远查不到，静默回落默认落点。
6. **遭遇抽牌默认与抽牌者交战**：`encounter.js` 的敌人分支会 `engage = resolvingSeat`，落点因此被拉回抽牌者所在地点。现在用 `printedSpawnLocation` 判据跳过默认交战。
7. **开局摆位不是「进入载具」**：运行面锁 `assetRule.vehicleAccessLocked` 一开始把 1–4 人开局摆车全挡了（4 个 `High Gear real Np setup` 用例红）。`enterVehicle(..., { setup: true })` 现在绕过锁定与敌方/威胁区限制。
8. **测试可能比引擎更错**：07213 的「+2 伤害不生效」折腾了两轮，最后发现是测试让调查员**站在渔船上**，而印刷正是「不在载具上才 +2」。写断言前先确认场景前提。
9. **共享接口漂移**：改 `resource-bank.js` / `vehicles.js` / `enemy-entry.js` 后 TCU 账本必红，按 `audit:tcu:player:write` → `audit:tcu` 顺序重建。
10. **忘了重建覆盖度产物**：改条目后不跑 `audit-abilities.mjs --write`，`覆盖度产物与当前实现一致` 会红。
